# #037 independent presentation/seek media corpus

Two small **real** H.264 MP4 bitstreams; committed as binary test inputs (not generated by a test mock). Generated on 2026-10-09 using local FFmpeg and verified independently with FFprobe.

| File | Source frames | FFprobe packet PTS (seconds) | Meaning |
| --- | --- | --- | --- |
| `037-pts-cfr-colors.mp4` | 12, 64×48: red 0–1s, green 1–2s, blue 2–3s | 0, .25, .5, .75, 1, 1.25, 1.5, 1.75, 2, 2.25, 2.5, 2.75 | 4 fps CFR, measured presentation intervals |
| `037-pts-vfr-colors.mp4` | 4, 64×48: red, green, blue, red | 0, .4, 1.12, 1.4 | VFR; declared *average* container rate is NOT the true time interval for all frames |

Generation recipe for CFR:

```sh
ffmpeg -f lavfi -i color=c=red:s=64x48:r=4:d=1 \
  -f lavfi -i color=c=green:s=64x48:r=4:d=1 \
  -f lavfi -i color=c=blue:s=64x48:r=4:d=1 \
  -filter_complex '[0:v][1:v][2:v]concat=n=3:v=1:a=0,format=yuv420p[v]' \
  -map '[v]' -c:v libx264 -threads 1 -preset ultrafast -crf 20 \
  -bf 0 -g 1 -movflags +faststart 037-pts-cfr-colors.mp4
```

Generation recipe for VFR: render a single 64×48 PNG each for red/green/blue with `ffmpeg -f lavfi -i 'color=c=red:s=64x48:r=1:d=1' -frames:v 1 red.png`, substituting color names. Then use FFmpeg concat demuxer with this file content:

```
file 'red.png'
duration 0.40
file 'green.png'
duration 0.72
file 'blue.png'
duration 0.28
file 'red.png'
```

```sh
ffmpeg -safe 0 -f concat -i concat.txt -fps_mode vfr \
  -video_track_timescale 1000 -vf format=yuv420p -c:v libx264 \
  -threads 1 -preset ultrafast -crf 20 -bf 0 -g 1 \
  -movflags +faststart 037-pts-vfr-colors.mp4
ffprobe -v error -select_streams v:0 -show_entries packet=pts_time \
  -of csv=p=0 037-pts-vfr-colors.mp4
```

`../subtitle-transform/037-vfr-color-cues.srt` encodes independently authored cues against the VFR timeline, with a *deliberate* 20 ms overlap on blue and a 40 ms final cue to exercise readability diagnostics. The SRT does not claim automatic frame alignment; the authored third cue begins 20 ms before blue's verified presentation timestamp.

Verification:

```sh
./node_modules/.bin/vitest run tests/video-subtitle-pts-037.test.ts
node tests/video-subtitle-seek-037.browser.mjs
```

Chromium browser acceptance uses actual uploaded local MP4/SRT `File`s at 390×844. It confirms decoded center-pixel color at each requested seek and reports actual presentation callbacks separately. A callback observed *after playback resumes* can reflect a **later** PTS than the requested seek. This is not frame-perfect extraction or proof on a physical phone, Safari, Firefox, hardware camera, or all codecs. The standalone browser acceptance does not certify the built application UI or its release bundle.
