# STR-419 — PDF/A-2b export, independent validator decision (2026-10-19)

**Decision:** GO for bounded local CLI (node scripts/pdfa-419.mjs input.txt output.pdf) only when veraPDF returns a compliant PDF/A-2b report on the exact candidate bytes. NO_GO for public browser PDF/A route or arbitrary PDF conversion: the browser cannot execute the independent validator. No production deploy in this ticket.

- Candidate exporter (developer CLI only, devDependency; no public deploy bundle): [PDFKit](https://github.com/foliojs/pdfkit), npm pdfkit@0.20.2, MIT, [v0.20.2 tag](https://github.com/foliojs/pdfkit/releases/tag/v0.20.2), tag object 8d72a71c3e2b03f3253c221065e9efcc69ca5b7d, September 2026. PDFKit supplies PDF/A-2b generation support but its own metadata assertion is not trusted.
- Font: Noto Sans Latin Regular from [Fontsource](https://github.com/fontsource/fontsource) @fontsource/noto-sans@5.2.8, OFL-1.1. Latin WOFF2 was converted to TTF and subset offline with fonttools (Basic Latin, Italian accented letters, euro and common punctuation): the bundled 16,032-byte TTF and OFL license are under src/engines/pdf/assets/. Unsupported code points are REFUSED to avoid silent missing-glyph output. Original 27,876-byte TTF is preserved in the MiniPC's local scratch and is not committed.
- Independent oracle: [veraPDF](https://github.com/veraPDF/veraPDF-apps) CLI ghcr.io/verapdf/cli:v1.31.202, image digest sha256:8cac3d462f6ef749c619b0973186cc9f949678600b2c545bdce3762445b0aec4, published 2026-10-16. **GPL-3.0 / MPL-2.0 dual license: external validator tool ONLY, neither copied nor linked into product.** Copyleft adoption would require owner clearance.
- Other candidates rejected: Ghostscript installed, AGPL; MuPDF AGPL; pdfcpu upstream [#832](https://github.com/pdfcpu/pdfcpu/issues/832) does not provide complete PDF/A validation. No copyrighted binary from these tools ships with the product.

A project-specific wrapper is necessary because PDFKit alone cannot independently decide conformance. Only after a successful veraPDF validation of one document and the exact PDF/A-2b profile does the CLI save the output. Negative corpus covers non-embedded font, missing ICC output intent, invalid XMP PDF/A part, attachment, and unavailable validator. Decision states are VALIDATED_PDFA_2B, REFUSED or NOT_RUN. Every failure leaves the output unlabeled and unwritten. Input is bounded UTF-8 plain text, not arbitrary PDFs. Docker container runs with network disabled. Docker may fetch its pinned image from the registry on first use (no document bytes are sent); for offline operation pre-pull the image referenced above. If Docker or the validator is unavailable, the command returns NOT_RUN.

Reproduce: npx vitest run tests/regroom-str-419.test.ts --maxWorkers=1, then npm run check && npm run build. Consumer after full npm ci with dev dependencies: node scripts/pdfa-419.mjs input.txt output.pdf; JSON contains status, profile and SHA256. Reopen independently with veraPDF -f 2b on the written output. New public PDF/A route is intentionally disabled until runtime validation can be provided. No existing route claims PDF/A.
