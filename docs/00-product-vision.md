# Product vision

## Problem

Knowledge workers repeatedly leave their main applications to solve tiny jobs: clean a CSV, compare lists, resize an image, calculate a rate, remove URL tracking, convert a file, inspect a PDF, compute business days, compare timezones, normalize a table, hash a file, generate a QR, check a margin or prepare something for a client.

Each job is small. Collectively they create a lot of switching, search and repeated setup.

Existing utility sites mostly optimize for feature count and SEO landing pages. Existing workspaces mostly optimize for project management, CRM, documents or AI assistance. UtilityOS explores the space between those categories.

## Product promise

A personal utility workspace that starts with the tools relevant to how you work, then stays modular.

The user should not begin by browsing 200 cards. Onboarding should produce a useful starting workspace and then get out of the way.

## Initial target

Research priority:
1. freelancers;
2. consultants;
3. solopreneurs;
4. creators doing professional client/business work;
5. small-agency operators;
6. broader knowledge workers later.

This is a wedge, not a permanent exclusion boundary.

## Jobs to be done

Five broad verbs:
1. prepare;
2. convert;
3. clean;
4. compare;
5. calculate.

Verification/proof utilities can become a sixth family where useful.

## UX north star

Home should feel personal and small:
- Your Tools
- Recent
- Suggested additions
- Search / command palette
- Tool library drawer

The full catalog exists, but should not dominate first-run experience.

## Non-goals

- not an ERP;
- not a CRM;
- not a project manager;
- not generic AI chat;
- not automation/orchestration infrastructure;
- not TinyWow with more tools;
- not an Italy-only fiscal website;
- not developer-only.
