# #370 — CSV/XLSX fidelity, donor review and NO_ADOPT decision

**Audit date:** 2026-10-11. **Repository baseline:** `42562bb4` (`main`, initially clean). **Scope:** read-only feasibility of already-installed local CSV/XLSX APIs and candidate donors. No library swap, runtime patch, transitive package adoption, account/network integration, or release approval.

## The actual installed path

| Surface | Pinned source and license | Observed contract and limitations |
| --- | --- | --- |
| CSV | `papaparse@5.7.0` **MIT** in local `node_modules` and `package-lock.json`; `src/engines/table/csv.ts` | Parses strings with `dynamicTyping: false`; 50 MiB hard input / 100,000 rows / 2,000,000 cells. Serializing CSV escapes formula-looking cells by adding a leading apostrophe. This intentionally changes exported formula-like text. |
| XLSX import | `read-excel-file@9.3.10` **MIT**, `src/engines/table/spreadsheet-interchange.ts` | Reads sheets and converts selected sheet values to CSV; multiple sheets require explicit selection; does not preserve source workbook, formulas or formatting. Formula cells without caches become blank; stale cached results can be exposed as values. Import bound 10 MiB compressed bytes, 64 sheets / 100,000 rows / 512 columns / 500,000 selected-sheet cells, but validation is **after** parsing/decompression. ZIP-bomb upper bound and macro/relationship preflight not verified. |
| XLSX write | `write-excel-file@4.1.1` **MIT**, same app seam | `tableToXlsx` writes **one** sheet with default string cells; only explicit `number` / ISO `date` policies coerce. Source leading zeros and date-like text remain strings by default; formula-looking source values remain inert strings. Output capped at 20 MiB after creation, not a full memory cap. |
| Other installed XLSX producer | `src/engines/pdf/pdf-table-xlsx-254.ts` uses pinned writer | Explicit selected PDF table only: one XLSX sheet, all text, no formulas or styles. This is not an arbitrary multi-sheet spreadsheet editor. |

Exact package artifacts and integrity are recorded in the existing `package-lock.json`; no changes to the lockfile were made. License assertions for direct packages were checked against their installed manifests and local `LICENSE` files; transitive license obligations require a separate full release SBOM scan before any replacement.

The openpyxl-backed cases use `it.skipIf(!process.env.SPREADSHEET370_PYTHON)`. **A regular npm/Vitest run with that variable unset skips the independent oracle; its green exit is NOT AC-370.3 proof.** The exact command above is mandatory to claim independent readback. Both generators and readers run offline against generated byte buffers; test fixtures are synthetic, no real user spreadsheet is modified.

| Probe | Measured result | Claim |
| --- | --- | --- |
| 2 sheets | XLSX import refuses implicit selection (`SHEET_SELECTION_REQUIRED`); selecting sheet `Secondary` yields `00007` and ordered sheet names | **SUPPORTED**: reading a selected sheet only; multi-sheet output roundtrip **NOT_SUPPORTED** by public writer |
| Text vs typed numeric/date | Independent openpyxl `data_type`: ID `00123` → `s`; number `12.50` → `n` / `12.5`; date `2026-02-21` → `d` / midnight; `=1+1` → literal `s` | **SUPPORTED** for chosen column policies only; full original type/style fidelity **NOT_SUPPORTED** |
| CSV formula injection | CSV unparse prefixes apostrophe to `=HYPERLINK(...)` and `+42`; 00123 / 00007 still textual | **SUPPORTED** export escape; source content intentionally changed to prevent spreadsheet interpretation |
| Input formula and hyperlinks | Python fixture containing `=1+1`, `=HYPERLINK(...)` and hyperlink target `https://example.invalid/external` yielded blank formula cells and `OPEN` link display text | Formula **NOT EVALUATED, NOT PRESERVED**. Hyperlink target not present in CSV, but there is **no general hostile-link security certification** |
| Stale formula cache | Synthetic XLSX `=1+1` with forged cached result `777` yielded `777` as CSV | **NO_GO** for any calculated/correct formula-value promise; cached value is untrusted |
| Macro marker | Synthetic OOXML with macro-enabled workbook content-type and `xl/vbaProject.bin` marker parsed successfully as `id\n00123` | **NO_GO** for promised macro refusal / XLSM sanitization. Marker was **not** executable VBA; this probe disproves a generic rejection guarantee but does not certify actual VBA execution or security |
| Malformed / oversized input | Invalid ZIP rejected `XLSX_READ_FAILED` with original bytes unchanged; >10 MiB raw buffer rejected `FILE_TOO_LARGE` | **SUPPORTED** at these tested bounds, not a full ZIP expansion / cancellation test |
| Bounded perf | 2,000 data rows × 6 columns + header = **12,006 cells**; XLSX **61,512 bytes**, three local write→read→CSV samples, **p50 166 ms**, maximum **172 ms**; separate openpyxl readback **220 ms** | **Measured on this Mac only**; not mobile, not worst-case, no portable SLA established |

**Unsupported / NOT_RUN:** preserving formula expressions from input XLSX, recalculation, multi-sheet workbook roundtrip, formatting/styling, charts/merged cells, macros/VBA, external-reference policy enforcement, comprehensive ZIP-bomb screening, complex numeric precision, cross-timezone/date system nuances, cancel/abort during parsing (no signal in current API), physical Safari/Android or mobile memory/CPU. No security assurance follows merely from converting hostile XLSX to CSV. Input buffers remain unchanged by tests, but app-level undo/cancel and complete prior-state preservation are NOT_RUN.

**Recommendation:** keep the pinned JS path for small local value-only conversions, with the limitations above stated explicitly. Do not replace it with any donor or call it an XLSX editor, a formula evaluator, a macro scanner, or a safe original-file roundtrip. Before extending capability, require a verified pre-parse OOXML threat gate with bounded decompression and explicit macro/external-reference policy, then measured browser/mobile fidelity tests on valid complex workbooks; independently verify styles/formulas and data loss. The separate `src/engines/ooxml/package.ts` has macro-policy logic, but the public spreadsheet interchange path inspected does not call that checker; it is **not** proof of protection on this path.
