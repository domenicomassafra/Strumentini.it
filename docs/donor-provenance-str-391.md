# STR-391 — riuso e provenienza (22 ottobre 2026)

Questa modifica usa le funzioni locali già presenti `parseCsvTable` e `serializeCsvTable` (`src/engines/table/csv.ts`) e `filterTable`, `joinCsvTables`, `assertBoundedTable` (`src/engines/table/operations.ts`). Per il parsing/serializzazione i moduli esistenti dipendono da [PapaParse 5.7.0](https://github.com/mholt/PapaParse), licenza **MIT**, upstream commit di riferimento `e78dddce4764a3465e86f3a2fddd0a1bcfc854be` (09/10/2026, citato anche nel dossier #149); l'eventuale range nel manifest npm viene risolto dal lockfile del repository. Nessun sorgente donor è stato cambiato o vendorizzato.

Interfacce native usate: Web Crypto `crypto.subtle.digest('SHA-256')`, `AbortController`, `File.text`, `Blob` e download mediante object URL. Nessun package runtime aggiunto. Il gap specifico di STR-391 è la **composizione tipizzata e salvabile** di operazioni esistenti, con convalida integrale dello schema/versione prima dell'esecuzione, impronte degli input e dell'export, trace leggibile e annullamento atomico. Il JSON salvato dopo l'esecuzione include hash sorgenti e hash output attesi per il replay verificato anche dopo aver riaperto il browser; modificare sorgenti/passi nella UI apre una nuova esecuzione senza riutilizzare ricevute obsolete. Una libreria di workflow generica introdurrebbe esecuzione e persistenza non necessarie; l'adapter tipizzato è limitato a tre tipi di passo già supportati.

Integrazione in attesa: #147 / PR #386 per la preview annullabile dei singoli trasformatori e #149 / PR #387 per le politiche aggiuntive su join, duplicati e precisione. La pipeline usa per ora il join **testuale** del motore su main, sempre con `nullKeyPolicy: never-match`; non afferma di coprire il join a precisione decimale di STR-390. Nessun rilascio in produzione senza #162.
