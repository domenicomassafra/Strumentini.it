## Differential behavior and limits

The public canonical local `generateQr` is retained for tests, independent decoder and explicit runtime fallback; the generator tool now calls `generateQrDonor278`. The adapter enforces the pre-existing limits **byte-mode UTF-8, EC-L, versions 1–4, 78 bytes maximum, 4-module quiet zone**, validates mask 0–7 and disallows empty input before entering donor code. Donor creates exactly one byte-mode segment with fixed version and EC level, never chooses a larger version or silently coerces an unsupported payload. Its matrix is rendered with the *existing* SVG encoder and `data-matrix` attribute for reader compatibility; PNG export continues to consume that same matrix. In the unlikely event qrcode fails, `engineVersion` explicitly identifies the proven local fallback.

MiniPC Node 26.12.0 on 2026-10-20, independently sampled corpus: **21/21** payloads decoded with independent jsQR and legacy QR reader, **168/168** forced-mask matrices byte-identical; auto masks differ in 7/21 because local penalty omitted ISO finder rule N3 (the independent donor N3 selection matches all 21/21). Both encoders deterministic across 50 repeats. Input empty/79 bytes: donor alone accepts but the *adapter refuses* as the original implementation. On 1000 repetitions of a representative UTF-8 URL, local 780 ms/16.82 MiB sampled heap vs donor 344 ms/13.23 MiB sampled heap, one environment-specific sample, no guaranteed SLA. Browser minified/gzipped module comparison: local QR core 6062/2667 B, donor core 20877/8081 B, public qrcode bundle 24901/9695 B. Added JS is loaded only when the user submits QR generation; 3x lazy chunk size is an acknowledged tradeoff for reduced encoding CPU, not an initial page penalty.

Regression suites: `tests/qr-qrcode-278.test.ts` and `tests/qr-local-engine.test.ts` (38/38 PASS). Browser acceptance: `tests/regroom-str-278.browser.mjs` against compiled Astro output on existing MiniPC Chrome 155 CDP at 390 px, with no POST/egress and verifiable SVG. Physical Safari mobile, Android device RAM/thermal and distribution-level release admission remain NOT_RUN/blocked separately, not silently promoted to Gold.
