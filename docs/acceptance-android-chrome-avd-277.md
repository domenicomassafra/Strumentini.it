# STR-277 / issue #105 — Android Chrome emulator acceptance

The owner changed the issue's original physical-phone requirement on 19 October 2026: Android Emulator + installed Chrome is sufficient for this issue, provided every receipt clearly says **SIMULATED**, never physical hardware. This is a source/compiled-consumer acceptance only and does not independently certify Gold or a production release.

The test launches the existing `str277-api35` AVD (Android 15 API 35, emulator 37.2.12, `sdk_gphone64_x86_64`, software GPU), opens the compiled `/tools/image-resize/` page in **the installed Android Chrome**, chooses `tests/fixtures/android-chrome-avd-277-input.png` using Android's actual native photo/files picker, sets 160×120, clicks Resize, then uses Chrome's native download flow. It pulls the saved JPEG from Android `/sdcard/Download/`, decodes the actual bytes with independently installed Sharp/libvips, and checks JPEG magic, MIME, dimensions, pixel count, file length and SHA-256. A screenshot comes from `adb exec-out screencap -p` and is downscaled to remain under the agent file-size limit. The receipt preserves emulator OS fingerprint, Chrome version/user agent, source commit and compiled HTML SHA-256.

Negative cases run on the same emulator Chrome session: cancelling the native photo picker without selecting a file, and submitting a deliberately corrupt JPEG through the browser's file-input test interface (the latter is an injected browser fixture, **not** a second native-picker action). Both must produce no downloadable result. The page-level request log must show no offsite network requests. OS permission revocation and a physical device were not tested.

Validation: `npx vitest run tests/regroom-str-277.test.ts --maxWorkers=1` checks the fail-closed receipt contract and independently reopens the saved JPEG and screenshot. `npm run check && npm run build` verifies source and compiled assets. Heavy work runs on MiniPC under `flock -w 1800 /tmp/strumentini-it-heavy.lock`; the consumer is served on loopback with `adb reverse`, so no image data is uploaded to a service. The private `.tmp-str277` SDK download/logs are excluded from Git.

Existing, unchanged dependencies used for this acceptance: Android SDK Platform Tools 37.0.1 and Emulator 37.2.12 (Google Android SDK), `@playwright/test@1.63.0` (Apache-2.0), `sharp@0.35.5` (Apache-2.0), and the existing resize donor `pica@10.0.3` (MIT). Their installed versions were read from the MiniPC runtime and are declared/pinned through the existing repository package lock. This ticket adds no runtime package, WASM, codec, licensed model or third-party source file. Redistribution clearance for the wider product remains governed by #126.

Evidence generated by the acceptance script (never hand-edited): `quality/receipts/android-chrome-avd-277.json`, `quality/receipts/android-chrome-avd-277-output.jpg` and `quality/receipts/android-chrome-avd-277-simulated.jpg`.
