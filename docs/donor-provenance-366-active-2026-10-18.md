### Same PR #222: corrected classification with source-bound RED/GREEN

The former lock parser excluded every `devOptional` package and flagged seven real compatible edges as `DEV_ONLY`, although npm v3 uses this marker for optional dependencies also reached via dev tooling ([npm lockfile documentation](https://docs.npmjs.com/cli/v10/configuring-npm/package-lock-json)). The checker now follows only **present** `devOptional` nodes reached by non-dev packages, required or optional peers, and root optional declarations; it verifies their full nested dependency metadata, strict semver ranges, SPDX and canonical npm source/SRI shapes. `dev: true` still fails for runtime edges. Actual `tslib@2.8.1` declares the valid [SPDX `0BSD`](https://spdx.org/licenses/0BSD.html), now recognized as *metadata only*. The CLI reports the 13 checked optional nodes separately from 367 non-dev rows: no extra product package or permission is inferred.

Four precisely named locally authored source/README/typing files are now marked `LOCAL_AUTHORED` with a fixed historical Git commit reference, exact Git blob SHA-1 and separate SHA-256 asset pin. `scripts/donor-local-authored-366.ts` verifies file bytes against the expected blob; **commit-tree membership is not independently rechecked in shallow CI**, and the marker proves neither authorship nor rights. No other path, including vendor executables/WASM/models, can use this classification. No arbitrary `MIT`, Apache or donor license is assigned to the local documentation.
