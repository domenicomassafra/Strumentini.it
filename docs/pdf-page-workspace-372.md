# STR-372 — workspace locale delle pagine PDF

Route pubblica: `/tools/pdf-page-reorder/` (manifest esistente `pdf-page-reorder`).

L'editor carica il PDF nel browser, legge il conteggio e rende **una pagina alla volta**, esponendo soltanto quattro miniature nel viewport mobile. La selezione resta associata ai numeri originali: spostare o trascinare una miniatura cambia l'ordine della copia, non i byte dell'originale. Sono disponibili selezione/deselezione, spostamento singolo, batch all'inizio/fine, inversione, e due risultati espliciti: riordinare tutte le pagine o estrarre solo quelle selezionate nell'ordine corrente. La seconda operazione rifiuta una selezione vuota.

Il browser usa il renderer e le primitive già attive in `src/engines/pdf/thumbnails.ts` (PDF.js, Apache-2.0) e `page-order-controls.ts`. Il modulo `workspace-372.ts` riusa `mutatePdf` / `buildPdfFromPages` nativi, con riapertura indipendente in `pdf-lib@1.17.1` (MIT) per verificare conteggio, dimensioni e rotazioni nelle posizioni richieste. Il risultato attraversa inoltre il gate PDF/Result v2 già attivo prima di poter essere scaricato. Né il reader PDF.js né il reparser pdf-lib dimostrano da soli l'identità visiva pixel-per-pixel; l'acceptance Poppler verifica anche testo e ordine sulle fixture 1/100 pagine. Riuso donor senza nuove dipendenze; identità e obblighi più ampi restano documentati in `docs/donor-provenance-366-active-2026-10-18.md`. La scelta #126 opzione B vieta reintrodurre `pdfstudio`, QPDF WASM e Mediabunny.

Il Worker è separato e terminato su risposta, cancellazione, eccezione o dopo 60 secondi. Budget: 25 MiB input, 50 MiB output, 200 pagine, quattro thumbnail da massimo 176×208 pixel renderizzate in sequenza. Blob URL delle anteprime revocati quando cambia pagina/sessione; i buffer del risultato sono temporanei. UI senza API remota, upload, telemetria PDF o persistenza automatica. Quando il file è troppo grande, cifrato, malformato o ambiguo, nessuna copia parziale è proposta; l'input rimane disponibile.

Prove previste: `npx vitest run tests/regroom-str-372.test.ts tests/regroom-str-372-worker.test.ts --maxWorkers=1` su MiniPC Node26; `npm run check && npm run build`, `npm run deploy:check` (solo dry-run) e `node scripts/acceptance-pdf-workspace-372.browser.mjs` con build statica, Chromium 390px e riapertura via `pdfinfo`/`pdftotext`. Prove fisiche e Gold: **NOT_RUN/NO_GO**; nessun deploy.
