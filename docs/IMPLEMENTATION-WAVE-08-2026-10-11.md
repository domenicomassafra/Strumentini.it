- `npm test -- --maxWorkers=2`: **PASS**, **256/256 files, 1,953/1,953 tests** after post-review protocol and download-policy regressions, including ticket/dashboard, format/certification/catalog and original-200 functional audit. Ticket dashboard retains **424 total, 293 completed (17 administrative refusals), 131 open**, 0 status mismatches.
- `npm run check`: **PASS**, Astro/TypeScript **1,996 files, 0 errors, 0 warnings, 22 pre-existing informational hints**.
- `npm run build`: **PASS, 292 static pages**, asset inspector PASS (686 JS assets; 7,915 bytes initial route JS; 291 unique metadata pages; 285 sitemap entries).
- `tsx scripts/validate-release.ts --no-write-receipt` run **after** build: **BLOCKED**, **8 blockers and 0 errors**: stale browser evidence; Gold receipt missing/not-Gold/source-stale; Android and iOS physical evidence missing; stale rollback; worktree dirty during wave. No receipt written. Running the validator during the static build can transiently report missing pages, so only the **post-build** result counts.
- `git diff --check` **PASS**. Source/browser evidence is local, not a release or staging certification.

**Two-axis review findings and corrections:** a denied preference `removeItem` cannot be displayed as revoked while an `enabled` value survives; the three JSON/CSV/WAV controls now read back persisted state and expose the error rather than claiming a false OFF. File-privacy input changes clear the previous result rather than associating an old downloadable artifact with changed inputs. The security review also found and corrected the CI omission for `ephemeral-file-handoff-337.ts` and early rejection/cleanup on invalid protocol payload; the receiver discards a capability fragment even when its opener is absent. The global unit suite above was rerun after these source changes. Native browser/OS acceptance remains scoped to each individual test report. Synthetic positive #347 receipt fixtures are not the official real Gold issuance pipeline, and #337's Vite component harness is not the full Astro route.

**Hydration regression, verified after review:** with a persisted `enabled` key, Astro SSR initially rendered an unchecked box while the Preact client also initialized its state directly from storage; without a state change the actual DOM box could stay incorrectly unchecked. All three download UIs now initialize state to `false` (matching SSR), then re-read actual browser consent on mount to cause the necessary client state transition. An initial revised WAV Chromium run **FAILED** at the reload checkbox check; after this correction the exact `node tests/acceptance-download-wav-339.mjs` script **PASS** (byte-identical PCM16, denied `removeItem` leaves checkbox visibly ON and warns, persisted ON after reload, successful subsequent revoke, no unconsented download or network egress). JSON browser regression passed in the worker's prior source snapshot; CSV browser regression was inconclusive due to local development-island hydration timeout. Neither result is generalized to physical devices, and #339 remains open.
