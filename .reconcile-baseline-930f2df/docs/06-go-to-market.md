# Go-to-market hypothesis

## Principle

**Individual utilities acquire users. The personal workspace retains them.**

If users never return through the workspace, the product has no meaningful advantage over a normal utility directory.

## Funnel

1. User lands on a specific high-intent tool.
2. Tool works before signup.
3. CTA: Add this to my tools / Install this pack.
4. Short onboarding asks only context that changes recommendations.
5. User sees a generated workspace.
6. Optional sign-in enables cross-device sync.
7. Usage improves recommendations.
8. Shareable pack links create referral loops.

## Acquisition surfaces

### Tool pages

Prioritize tasks involving files, CSV, PDF, comparisons, transformations, multi-step calculations and profile context.

Commodity one-number calculators can exist, but should not dominate investment.

### Profession pages

Initial candidates:

- consultants;
- freelancers;
- marketers;
- creators;
- researchers;
- developers.

Each page should sell a useful starter pack, not exist as SEO filler.

### Pack sharing

Allow public pack links containing selected tools and optional layout/description.

Example:

creator publishes "My consulting toolset" -> audience previews -> installs -> personalizes.

### Open source

Potential OSS surfaces:

- tool manifest/schema;
- deterministic utility engine;
- selected utilities;
- contribution templates.

This can support GitHub distribution and technical trust.

### Product/community launch

Use Product Hunt after the workspace/onboarding interaction is real.

Hacker News is more credible if the story genuinely includes local-first execution, open source, deterministic browser compute and no unnecessary AI.

Launch specific packs into the communities they serve instead of advertising a generic toolbox.

## Content

Avoid a generic AI-written blog.

Prefer:

- tool-pack pages;
- workflow explainers;
- transparent methodology;
- changelog/new-tool notes;
- user-created pack showcases.

Low-frequency newsletter:

> **3 small tools worth adding this month.**

## Retention metrics

Track:

- tools added per activated user;
- 7-day and 30-day workspace return;
- number of distinct tools reused;
- percentage of uses launched from workspace versus search landing;
- pack installs;
- profile defaults reused;
- command palette usage;
- shared-pack installs.

If users only arrive once from search and never return, the workspace thesis is failing.

## Monetization

Do not monetize before retention is visible.

Later candidates:

- cross-device sync;
- multiple profiles;
- saved presets;
- advanced history;
- custom/private packs;
- team packs;
- optional no-ad plan if ads are ever introduced.

Keep normal deterministic utilities free enough to preserve trust and acquisition.

## Launch proof required

Before broad launch:

1. onboarding creates meaningfully different workspaces for at least four roles;
2. each role has 8–12 genuinely useful starter tools;
3. shared defaults work across at least three tools;
4. at least one tool-to-tool handoff is genuinely useful;
5. anonymous first use works;
6. account sync is optional;
7. one pack can be shared/imported.
