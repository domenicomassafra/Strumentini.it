# Onboarding, profile and packs

## Onboarding hypothesis

The first-run flow should be short enough to finish but useful enough to change the workspace.

Candidate questions:
1. What kind of work do you do?
2. Employee / freelancer / consultant / business / student / mixed?
3. Country / locale.
4. Currency and timezone.
5. Which recurring tasks do you perform?
6. Which file/data types do you handle?
7. Which packs sound useful?

Optional free text can describe the job in one sentence and suggest tools. All resulting choices remain editable.

## First-run outcome

Do not install everything.

Generate roughly 10–15 relevant starter tools, explain why they were selected, then let the user keep all, remove tools, add packs or browse the full library.

## Pack candidates

- Independent Work
- Marketing
- Content / Creator
- Research / Academia
- Developer / Data
- Office / Admin
- Finance-lite

Packs are curated groups, not permission boundaries.

## Shared profile hypothesis

The UX advantage to test is: enter stable defaults once; compatible tools reuse them.

Examples: EUR is already selected; timezone starts at Europe/Rome; business-day tools know the workweek; rate calculators reuse day/hour rate; date tools use the preferred format.

Every reused value must be visible and overridable.

## Portability

Workspace configuration should eventually support export/import:
- installed tools;
- enabled packs;
- layout;
- safe defaults;
- preferences.

Do not include user files by default.
