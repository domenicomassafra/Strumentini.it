# Heavy local feasibility refresh

This spike is the reproducible evidence harness for expansion ticket 34. It measures browser-local HEIC, Italian OCR, Office, advanced PDF, audio, and video candidates without wiring any of them into production tools.

The harness deliberately keeps production promotion separate from “the demo ran.” Every candidate ends as `SPIKE` or `DENY` in this tranche. Genuine iOS Safari and Android Chrome receipts are still `NOT_RUN`, full process/WASM/native memory is not measured here, and the runtime/cancellation contracts are intentionally left for the downstream worker and physical-device tickets.

## Reproduce

From this directory:

```bash
npm ci
npm run bench
```

`npm run bench` prepares the corpus and local Tesseract assets, records exact npm metadata and audit findings, builds the Vite production spike, runs the real-file corpus in available desktop engines, records lazy bundle sizes, builds the decision matrix, and executes invariant tests.

The desktop harness tries system Chrome and Edge plus Playwright Chromium, Firefox, and WebKit. An unavailable executable is recorded as unavailable rather than silently replaced. Playwright WebKit is classified as a desktop regression engine; it is never treated as Safari or iOS evidence.

## Evidence outputs

Generated receipts live in `quality/benchmarks/heavy-local-feasibility/`:

- `package-metadata.json` — exact npm versions, license, integrity, unpacked size, modification time, repository.
- `npm-audit.json` — the audit result for the installed benchmark graph.
- `bundle-sizes.json` — production Vite chunks plus gzip measurements and local OCR runtime assets.
- `desktop-runtime.json` — per-engine real-file results, runtime, JS heap observations, capability probes, same-origin requests, and blocked external requests.
- `decision-matrix.json` — candidate decisions, format surface, bundle/runtime/memory evidence, security/license gates, cancellation status, mobile status, and family fallback boundaries.

The historical human-readable decision summary is
`docs/RESEARCH-DECISIONS-2026-10-27.md`; the exact measured decisions remain
in the version-controlled benchmark JSON named above.

## Corpus

`public/corpus/` contains small real binary files rather than JSON mocks: HEIC, Italian OCR PNG, XLSX, DOCX, PPTX, PDF, PCM WAV, and H.264/AAC MP4. `manifest.json` records byte size, SHA-256, and provenance for every fixture.

The checked-in HEIC/media raster fixtures were created locally from deterministic content with macOS `sips`, FFmpeg, and Pillow. Office/PDF fixtures are generated by the exact candidate libraries when missing and then preserved, so routine benchmark runs do not rewrite them. Tesseract worker/core/language assets are copied from the exact installed packages into ignored `public/tesseract/` files before the build; they are measured but not checked in.

## Locality and memory boundary

The benchmark server binds only to `127.0.0.1`. Each browser context aborts any request that is not loopback, `blob:`, or `data:` before transmission. Italian OCR explicitly points Tesseract to same-origin worker, core, and traineddata assets instead of its normal CDN defaults.

Chromium engines expose `performance.memory`, so the receipt samples JS heap while operations run. That is useful comparative evidence, but it excludes WASM linear memory, native decoded surfaces, graphics allocations, and full browser process RSS. The matrix therefore cannot use these numbers as a production memory acceptance gate.

## Physical-device boundary

No viewport emulation, mobile browser descriptor, desktop WebKit build, or desktop Safari-like user agent counts as physical evidence. The matrix keeps both required physical lanes explicit:

```text
iOS Safari     NOT_RUN
Android Chrome NOT_RUN
```

Any future `ALLOW` decision for these heavy local paths must attach genuine device receipts together with the capability/resource preflight and cancellation/memory acceptance required by tickets 100, 101, and 206.
