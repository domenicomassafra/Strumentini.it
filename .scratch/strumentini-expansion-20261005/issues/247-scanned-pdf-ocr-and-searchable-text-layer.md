**2026-10-10 experimental bounded implementation (production still blocked):** A `noindex`, **DEV-only** route `/tools/pdf-scansionato-ocr-247/` now accepts PDFs locally (≤8 MiB, ≤3 pages, ≤2 scanned pages, ≤2 MP/page). Its dynamic Astro `[...route].astro` exports zero static paths in production (pattern accepted for #241); an isolated production build generated **exactly 291 pages and no `/tools/pdf-scansionato-ocr-247/index.html`**. `src/engines/pdf/ocr-searchable-247.browser.ts` renders each PDF.js page, refuses to OCR any page with existing selectable text, lazily invokes the same-origin experimental `tesseract.js@7.0.0` Italian model from #246 for actual word-level OCR confidence and bounding boxes, and runs an abortable worker with a 120s/page timeout. `src/engines/pdf/ocr-searchable-247.ts` appends PDF text rendering mode `3 Tr` (invisible but extractable text) with measured word coordinates and WinAnsi glyph validation, copying the original source page drawing streams byte-for-byte. It rejects unsupported/interactive/signed/encrypted/rotated or unreadable pages instead of guessing.

**Real checks:** `tests/pdf-ocr-searchable-247.test.ts` **3/3 PASS** includes source image stream byte preservation, PDF.js reopen and real scanned-image document, two-page mixed scanned+digital content and cancellation/unsupported coordinates/glyphs. `node --import tsx tests/ocr-247-local-browser.acceptance.mjs` **PASS in headless Chromium 390px** on the SHA-pinned 1280×240 Italian scan (fixture hash `1bfc71b54560679f6b6d0e8f978201b2ca27fdfcd84d47ef9344d41db0a2f27b`) embedded as a real JPEG PDF and a separate two-page scanned+digital PDF; every downloaded output independently reopened with Node PDF.js and contains actual searchable OCR words (including `Fattura`, `numero`, `12345`, `678,90`). The digital source page text remains unchanged, no OCR duplication occurs, and original/output PDF.js render comparison measured **0 different pixels and 0/255 max-channel difference on every page** (threshold ≤0.05% changed pixels, ≤3/255 max-channel delta). Same-origin lazy WASM/model requests, no offsite requests or JS errors; digital-only PDF refuses output without starting OCR, cancellation yields no downloadable artifact. This verifies only the narrow measured desktop subset.

**2026-10-10 worker-10 narrow technical safety completion (still experimental/blocked):** The existing local `noindex` candidate now checks the source PDF **before the large OCR model loads**, refusing unsupported page geometries (rotated, nonzero CropBox/UserUnit), encrypted/signed pages and interactive catalog/page structures. It requires worker/WASM/image-decode support before reading the PDF. Its word overlay enforces finite word coordinates and source image limits, confidence **at least 45/100 per word and 75/100 for the full page** (Tesseract scores are uncalibrated risk filters, never accuracy guarantees), bound on output **16 MiB**, and UTF-8/WinAnsi glyph refusal without guessing unsupported characters. A 90° **sideways raster scan** built from the pinned Italian invoice is refused by the actual browser Tesseract run (instead of exporting unreliable text). The original selectable/digital text is untouched on pages with existing PDF.js text content, and pure born-digital PDFs never start OCR. Successful export still requires independent PDF.js reopen/text extraction and per-page source/output pixel comparison at the declared tolerance (measured **0 changed pixels, 0/255 maximum channel difference** on both real scanned and mixed fixtures).

**Resource/cancellation changes and evidence:** The workflow previously retained all pages' RGBA arrays across a long Tesseract recognition. It now discards those arrays after each page, re-renders the original source on demand during post-output pixel verification, and releases every native canvas in `finally`; at most two page RGBA buffers are needed simultaneously for the visual comparison rather than preserving all three across OCR. Worker termination is idempotent, including cancellation while the Tesseract worker is still being created; aborted renders destroy the canvas, and component unmount cancels any running job. The browser harness now waits for an **actual Tesseract Worker creation, cancels the active job, and waits for its `close` event**. End-to-end real PDF scan/mixed/sideways/interactive/cancel/no-offsite cases all pass independently in **desktop Chromium, Firefox and WebKit** at 390px (three receipt files under `.scratch/strumentini-expansion-20261005/evidence/ticket247/*-390-local-ocr.json`; source-pinned Chromium screenshots there). `tests/pdf-ocr-searchable-247.test.ts` verifies real source image-byte preservation, 2-page digital+scan content, PDF.js text and the first word's independently reopened geometric bounding box, plus low-confidence/malformed/rotated/interactive/abort refusal. Asset/model checks and no offsite requests are asserted.

**Production and truthfulness boundary unchanged:** The tests above use desktop engines emulating a narrow mobile-width viewport and one legible upright Italian invoice.
