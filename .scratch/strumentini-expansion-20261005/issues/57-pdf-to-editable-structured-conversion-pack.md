# 57 — PDF-to-editable/structured conversion pack

**What to build:** Add truthful PDF outbound conversions: PDF→Markdown, PDF→DOCX semantic reconstruction, PDF tables→XLSX, and PDF→PPTX page-as-slide baseline; allow editable reconstruction modes only where a fidelity corpus proves them, with OCR handoff for scans.

**Traces to:** US-EXP-04, US-EXP-10; AC-04.1, AC-05.1, AC-06.1, AC-10.1; DEC-EXP-01, DEC-EXP-05, DEC-EXP-06; C-EXP-05, C-EXP-08

**Constraints:** Never sell arbitrary visual PDF→XLSX as a spreadsheet; table extraction is table extraction. Page-as-slide PPTX is distinct from editable object reconstruction. Scanned PDFs require OCR and must say so.

**Blocked by:** 252, 253, 254, 255.

- [x] PDF→PPTX baseline preserves each page visually as a slide; any editable mode is separately labelled/proven.

**2026-10-10 implementation and closure of the three original bounded AC (worker-3):** The existing `/tools/pdf-to-markdown/` route now offers an independently selectable PDF→Word DOCX option in addition to the established page-labelled Markdown export (#252). New `src/engines/pdf/pdf-to-docx-57.ts` reuses existing page-scoped PDF text extraction and emits actual **editable WordprocessingML paragraphs** using local `fflate` ZIP encoding. Each document contains original filename, independently SHA-256 hashed PDF bytes, an explicit `Pagina PDF N di M` label for every source page, plus structure-loss warnings *inside the DOCX*: heading/list/table semantics, original reading order for columns, image/graphic/style/layout reconstruction and literal page breaks are unsupported. Arbitrary content is not guessed as a true heading/table; PDF text stays literal even with `& < > ** __` symbols. On generation, the finished OOXML document is reopened with the existing independent package analyser and semantic extractor; every nonblank original text/provenance/warning paragraph must match in original order or export fails closed. Input caps: local PDF ≤8 MiB, ≤12 pages, generated DOCX ≤4 MiB. Textless/scanned, mixed pages without selectable text, encrypted, truncated, malformed and cancelled inputs provide **no DOCX**; UI provides a truthful **manual** `/tools/ocr-italiano-locale-246/` link where OCR is required. This source-only editable text reconstruction is distinct from full-fidelity visual/layout DOCX reconstruction, which stays unsupported under the former refusal #253/#269. The Markdown OCR warning also links to the actual manual OCR route. Navigational links expose the two verified separate conversion surfaces without duplicate catalog/manifest entries.

**Original AC 2 and 3 fulfilled by existing completed #254/#255:** `/tools/pdf-tables-to-xlsx/` requires a user-selected PDF page+rectangle, PDF.js-stroked closed 2D grid and unambiguous one-text-item-per-cell, previews the actual grid before accepting export, embeds source SHA/page/region, and refuses other content; actual `.xlsx` is independently reopened cell-by-cell, preserving text such as `00127` and literal `=2+2` (no formulas). `/tools/pdf-to-images/` offers the distinct 4:3 PDF→PPTX baseline: user chooses up to eight PDF pages, each is rendered to a real PNG embedded as exactly one image per slide, source order, aspect and original visual content are preserved inside the labelled page-as-slide baseline; **not editable object/shape reconstruction**.
