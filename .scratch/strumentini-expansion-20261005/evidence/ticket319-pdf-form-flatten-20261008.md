# STR-319 — Form inspection / safe PDF flatten, 2026-10-08

## Auditable contract

The existing PDF writer removes annotations and AcroForm entries rather than painting annotation or widget appearance streams into page content. Removing a visible annotation would lose information. The upgraded `pdf-flatten` route refuses any visually risky state with an explicit unsupported-capability error; it never generates a file in that case. The **supported safe subset** includes documents without visible page annotations and with only hidden widgets or standalone form fields that do not contribute to page appearance. Unsupported: any visible annotation, appearance requiring viewer generation (`NeedAppearances`), XFA, unverified annotation tree, orphan widget. No decryption/bypass, upload or silent rasterization.

`src/engines/pdf/form-annotation-audit.ts` inspects each page annotation for object ID, page index, subtype, flags, hidden state, appearance and bounding box and links logical AcroForm fields to widgets and page numbers. `src/tools/pdf-form-inspector` returns this inventory, including explicit per-PDF flatten capability. `src/engines/pdf/index.ts::flattenPdfVerified` returns `verification.before/after` with exact counts, source-validated capability reports, output reparse, extracted text and geometry/image-count stability, and no residual interactive page hooks. `src/components/tools/pdf/PdfFormAuditDetails.tsx` presents the inspect/verification facts without pretending to have run a full visual comparison inside the module.

## Evidence and limitations

- Unit tests: `tests/pdf-form-flatten-audit.test.ts` verifies 6 cases: hidden linked widget provenance, post-output safety, visible widget/Link refusal, no-annotation baseline, dynamic appearance refusal, malformed arrays and cancellation. `tests/pdf-document-tools.test.ts` retains existing route regression and is updated to expect refusal of visible links, not false success.
- Fixture: `quality/fixtures/pdf-gold/hidden-widget-form.pdf` generated by `tests/fixtures/pdf-form-annotation-fixture.ts` and used by the standard 20-route browser acceptance. It contains a hidden widget with an appearance stream and an AcroForm field, with visible page text outside annotations.
- `npm run acceptance:pdf-form-flatten`: **21/21 Chromium/Firefox/WebKit (390px)**. Inspects source field/page/widget IDs and risk flags, refuses visible widget without downloadable output, reopens the downloaded safe output for annotation/field disappearance and text, then **renders the original and output in PDF.js and requires 0 differing pixels** at the verified 176×208 thumbnail resolution. No off-site upload.
- This real-pixel regression proves only the tested bounded fixture/renderer cases; there is **no generalized promise of visual equivalence for every arbitrary PDF**. Full appearance painting for visible widgets/forms remains deliberately unsupported rather than simulated or marked certified. No claim of physical mobile acceptance, source-bound release Gold receipt or production deployment.
